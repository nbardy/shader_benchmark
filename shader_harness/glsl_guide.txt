WGSL Shader Programming Guide - Patterns for Success
====================================================

VERSION: WGSL (WebGPU Shading Language) via WGPU
RUNTIME: WGPU 0.20 native execution (Metal/Vulkan/DX12)
HARNESS: Renders fragment-only shaders with automatic vertex pipeline

⚠️ LIMITATION: WGSL forbids dynamic array indexing (GPU parallelism constraint)
- Cannot do: `array[runtime_variable]`
- Cannot do: unstructured loops over arrays
- Solution: Manual expansion patterns (see examples below)

WHY THIS MATTERS FOR LLM GENERATION
===================================
LLMs have minimal WGSL training data (~3 years old, ~2021+) due to:
✅ WGSL is new (standardized 2023-2024)
✅ Training data cutoff before wide WGSL adoption
✅ LLMs naturally default to GLSL patterns they know well
❌ GLSL patterns FAIL in WGSL (dynamic indexing forbidden)
❌ This is a hardware-level GPU constraint, not a compiler limitation

CRITICAL INSIGHTS FOR SHADER GENERATION
========================================
1. **Dynamic Indexing Problem**: GPU hardware processes pixels in parallel. Each pixel must follow the same code path. Dynamic array indexing breaks this guarantee.
2. **Manual Expansion Solution**: Expand all array indices at compile-time (use if/else or explicit variable definitions).
3. **Function Abstraction**: WGSL functions can still take parameters, allowing code reuse without dynamic indexing.

REQUIRED SHADER STRUCTURE
==========================

All GLSL shaders must use this format with vertex and fragment shader sections:

```glsl
#version 330 core

// VERTEX SHADER SECTION
#ifdef VERTEX_SHADER

layout(location = 0) in vec2 position;

void main() {
    gl_Position = vec4(position, 0.0, 1.0);
}

#endif  // VERTEX_SHADER

// FRAGMENT SHADER SECTION
#ifdef FRAGMENT_SHADER

out vec4 fragColor;

void main() {
    // Convert gl_FragCoord to normalized coordinates
    vec2 uv = (gl_FragCoord.xy - 512.0) / 512.0;  // For 1024x1024 canvas, center at origin

    // Your mathematical visualization code here
    vec3 color = computeVisualization(uv);

    fragColor = vec4(color, 1.0);
}

#endif  // FRAGMENT_SHADER
```

⚠️ IMPORTANT REQUIREMENTS:
- Use `#version 330 core` (compatible with Naga translation)
- Separate vertex and fragment code with `#ifdef VERTEX_SHADER` / `#ifdef FRAGMENT_SHADER` blocks
- Write output to `fragColor` in fragment shader
- Always set alpha = 1.0 (no transparency)

COMMON MATHEMATICAL FUNCTIONS
============================

Distance Functions (for SDFs):
```glsl
float sdSphere(vec3 p, float r) {
    return length(p) - r;
}

float sdBox(vec3 p, vec3 b) {
    vec3 q = abs(p) - b;
    return length(max(q, 0.0)) + min(max(q.x, max(q.y, q.z)), 0.0);
}
```

Matrix Operations:
```glsl
mat3 rotateX(float angle) {
    float c = cos(angle), s = sin(angle);
    return mat3(1,0,0, 0,c,-s, 0,s,c);
}

mat3 rotateY(float angle) {
    float c = cos(angle), s = sin(angle);
    return mat3(c,0,s, 0,1,0, -s,0,c);
}
```

Complex Numbers (as vec2):
```glsl
vec2 cmul(vec2 a, vec2 b) {
    return vec2(a.x*b.x - a.y*b.y, a.x*b.y + a.y*b.x);
}

vec2 cdiv(vec2 a, vec2 b) {
    float d = dot(b, b);
    return vec2(dot(a, b), a.y*b.x - a.x*b.y) / d;
}
```

COORDINATE SYSTEMS
=================

Screen to World Conversion:
```glsl
// For 1024x1024 canvas, center at origin
vec2 screenToWorld(vec2 fragCoord) {
    return (fragCoord.xy - 512.0) / 512.0;
}

// For arbitrary size with aspect ratio preservation
vec2 screenToWorld(vec2 fragCoord, vec2 resolution) {
    vec2 uv = fragCoord / resolution;
    uv = uv * 2.0 - 1.0;  // [-1, 1]
    uv.x *= resolution.x / resolution.y;  // Correct aspect ratio
    return uv;
}
```

PERFORMANCE GUIDELINES
====================

Loop Limits:
- Keep loop iterations < 100 for mobile compatibility
- Use early breaks when possible
- Unroll small fixed loops manually

Precision:
- Use `highp` for positions and complex calculations
- Use `mediump` for colors and simple operations
- Use `lowp` for flags and simple interpolants

Branching:
- Avoid divergent branching in tight loops
- Use `mix()` instead of `if/else` for simple cases

COMMON PATTERNS
==============

Anti-aliasing:
```glsl
float antialias(float d, float width) {
    return 1.0 - smoothstep(0.0, width, abs(d));
}
```

Color Mixing:
```glsl
vec3 mixColors(vec3 a, vec3 b, float t) {
    return mix(a, b, smoothstep(0.0, 1.0, t));
}
```

Mandelbrot Set:
```glsl
int mandelbrot(vec2 c, int maxIter) {
    vec2 z = vec2(0.0);
    for (int i = 0; i < maxIter; i++) {
        if (dot(z, z) > 4.0) return i;
        z = cmul(z, z) + c;
    }
    return maxIter;
}
```

ERROR AVOIDANCE
==============

❌ AVOID:
- Division by zero: `a / b` → `a / max(b, 1e-6)`
- Taking sqrt of negative: `sqrt(x)` → `sqrt(max(x, 0.0))`
- Infinite loops: Always have exit conditions
- Very large numbers: Keep values in reasonable ranges

✅ PREFER:
- Built-in functions: `length()`, `normalize()`, `dot()`, `cross()`
- GLSL swizzling: `vec3.xzy`, `vec4.rgb`
- Efficient distance fields for 3D rendering
- Procedural generation over texture lookups

This guide ensures your mathematical shaders will compile and run efficiently
while maintaining visual accuracy and mathematical correctness.
