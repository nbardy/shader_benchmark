⚠️ CRITICAL: select() FUNCTION SIGNATURE:
---------------------------------------------
The select() function in WGSL has a different signature than GLSL ternary operator.

WRONG (Missing arguments):
let result = select(value);  // Error: expected 3 arguments, found 1
let result = select(true_val, false_val);  // Error: expected 3, found 2

RIGHT (Complete signature - 3 arguments required):
select(false_value, true_value, condition)  // NOT (condition, true, false)

EXAMPLES:
- let color = select(vec3<f32>(0.0), vec3<f32>(1.0), x > 0.5);
  // If x > 0.5 is TRUE, returns vec3<f32>(1.0); if FALSE, returns vec3<f32>(0.0)
- let val = select(0.0, 1.0, is_active);
  // If is_active is TRUE, returns 1.0; if FALSE, returns 0.0

NOTE: The argument order is (false_value, true_value, condition) - different from ternary!

⚠️ CRITICAL: let vs var<function> - IMMUTABLE vs MUTABLE BINDINGS:
---------------------------------------------
In WGSL, you MUST use the correct binding type for your use case.

USE let FOR IMMUTABLE (READ-ONLY) VALUES:
- let my_value = vec3<f32>(1.0, 2.0, 3.0);  // Cannot change after this
- let result = my_value * 2.0;               // OK - no mutation
- WRONG: my_value = other_vector;            // Error: invalid left-hand side

USE var<function> FOR MUTABLE (CHANGEABLE) VARIABLES:
- var<function> accumulator = 0.0;           // Can change value
- accumulator = accumulator + 1.0;           // OK - mutation allowed
- accumulator += some_value;                 // OK - accumulation

CRITICAL PATTERN - LOOP ACCUMULATION:
This is a very common pattern in shaders:
```wgsl
var<function> result = vec3<f32>(0.0);  // MUST use var<function>!
for (var i = 0u; i < iterations; i = i + 1u) {
    result = result + some_contribution(i);  // Mutation requires var
}
return result;
```

WRONG (Using let for a variable you'll mutate):
```wgsl
let color = vec3<f32>(0.0);  // WRONG - you can't mutate a let binding
color = color + more_color;  // Error: invalid left-hand side of assignment
```

RIGHT (Using var<function> for mutable accumulator):
```wgsl
var<function> color = vec3<f32>(0.0);  // RIGHT - var allows mutation
color = color + more_color;            // OK - valid mutation
```

SUMMARY:
- **let** = Read-only, assign once at declaration
- **var<function>** = Can be changed multiple times in the function
- If you plan to mutate a variable, ALWAYS use var<function>, NOT let

NUMERIC LITERAL CONSTRAINTS (CRITICAL):
---------------------------------------------
⚠️ f32 floating-point literals have strict range and exponent limits.

f32 Range and Exponent:
- Valid exponent range: approximately ±38 (e.g., 1.0e10, 1.5e-5)
- INVALID: Exponents like e19726, e-19726, e1000 (out of f32 range)
- Maximum representable value: ~3.4e38
- Minimum representable value: ~1.2e-38

WRONG (Numeric Literal Overflow):
let x = 5.942e19726;  // Error: exponent out of range for f32
let y = 1.0e-50;      // Error: exponent out of range (smaller than minimum)

RIGHT (Valid f32 Literals):
let x = 5.942e10;     // Valid: exponent within range
let y = 1.0;          // Valid: simple integer
let z = 3.14159;      // Valid: typical floating-point
let w = 1.5e-5;       // Valid: exponent in range

GUIDANCE:
- Keep exponents within ±38 range
- Use normalized values: instead of 1e100, use 1.0 and multiply/divide as needed
- Cast integer results to f32 explicitly: f32(large_integer)
- For very large numbers, divide instead: (big / 1.0) works better than 1.0e100
